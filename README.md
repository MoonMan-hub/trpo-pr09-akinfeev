# Практическая работа №9. PHP MVC интернет-магазин: корзина, session и контроллер действий

Дисциплина: Технологии разработки программного обеспечения.

## Используемый подход

Это продолжение MVC-магазина из практической работы №8 (Router, View, контроллеры, репозитории, namespace и autoload). Состояние после работы 8 зафиксировано отдельным коммитом и тегом `after-work-8`, поэтому в истории видно, что добавлено в работе 9.

## Что сделано

- Корзина в session: добавление товара, изменение количества, удаление позиции.
- `GET /cart` показывает корзину, все изменения идут POST-запросами и заканчиваются redirect на `/cart`.
- Пустая корзина имеет отдельное состояние, обычная показывается таблицей с суммами и итогом.
- Счётчик товаров в меню (layout) обновляется после каждой операции.
- Flash-сообщение об успехе или ошибке показывается один раз.
- Страница `/check/cart` выполняет сценарии из `data/cart_scenarios.json` и сверяет количество и сумму.

Технологии: PHP 8.0+, HTML, CSS. Библиотеки и composer не нужны.

## Маршруты (routes.csv)

| Метод | Адрес | Контроллер | Действие | Что делает |
|-------|-------|------------|----------|------------|
| GET | `/`, `/catalog`, `/about`, `/product?id=N`, `/check`, `/missing` | Home, Catalog, Error | см. работу 8 | как в работе 8 |
| GET | `/cart` | CartController | index | показывает корзину |
| POST | `/cart/add` | CartController | add | добавляет товар (поле `product_id`), redirect на `/cart` |
| POST | `/cart/update` | CartController | update | меняет количество (поля `product_id`, `quantity`), redirect |
| POST | `/cart/remove` | CartController | remove | удаляет позицию (поле `product_id`), redirect |
| GET | `/check/cart` | CartCheckController | check | сценарии из `cart_scenarios.json` |

## Что хранится в session

| Ключ | Что лежит | Пример |
|------|-----------|--------|
| `$_SESSION['cart']` | только состояние корзины: id товара и количество | `[1 => 2, 4 => 3]` |
| `$_SESSION['flash']` | одноразовое сообщение (тип и текст), удаляется при показе | `['type' => 'ok', 'text' => 'Товар добавлен в корзину']` |

Названия и цены товаров в session не копируются, они берутся из `ProductRepository` при каждом показе корзины. Поэтому цена не может «устареть» или быть подменена в сессии.

Если ключа `cart` в session нет (первый заход, новая приватная вкладка), `CartService::items()` возвращает пустой список и предупреждений нет.

## Почему изменения выполняются POST-запросами

GET-запрос должен только показывать данные: его можно открыть из закладки, повторить, обновить страницу, его могут вызвать браузер при предзагрузке или поисковый робот. Если бы добавление было ссылкой (`/cart/add?id=1`), любое повторное открытие меняло бы корзину. POST используется для действий, которые меняют состояние. После POST выполняется redirect на обычный GET `/cart`, поэтому обновление страницы (F5) не повторяет действие.

## Где считается стоимость

Только в `CartService` (`src/Service/CartService.php`):

- `lines()` считает стоимость позиции: цена товара * количество;
- `total()` суммирует позиции в общую стоимость.

Представления (`views/cart/index.php`) только выводят готовые числа через `money()`. Каждый товар хранится в корзине один раз, поэтому сумма не дублируется.

## Выбранный подход: CartService

Выбран `CartService`, а не модель `Cart`. Объяснение: корзина состоит из состояния в session и операций над ним, при этом ей нужны данные товаров из репозитория. Сервис хранит правила (проверка товара, лимит количества, расчёт суммы), а модель-данные остались бы пустой оболочкой над массивом. Сервис получает в конструктор `ProductRepository` и ссылку на массив с сессией (`$_SESSION`). Благодаря ссылке тот же класс проверяется на временном массиве, не затрагивая настоящую сессию.

## Правила количества

- Количество это целое число от 1 до 99 (`CartService::MAX_QUANTITY`).
- Не целое, ноль, отрицательное или больше 99: изменение не выполняется, показывается сообщение об ошибке.
- Для удаления позиции есть отдельная кнопка «Удалить».
- Товар, которого нет в каталоге, добавить нельзя.

Верхняя граница 99 добавлена мной, в задании её нет.

## Сценарии из cart_scenarios.json

Страница `/check/cart` берёт шаги `add:ID`, `remove:ID`, `set:ID:КОЛИЧЕСТВО`, выполняет их настоящим `CartService` над временным массивом и сравнивает результат с `expected`. Дополнительно выводится сумма по ценам из `products.json`.

| № | Шаги | Ожидается | Сумма |
|---|------|-----------|-------|
| 1 | add:1, add:1, add:2 | товар 1: 2 шт., товар 2: 1 шт. | 4 300 ₽ (900 * 2 + 2 500) |
| 2 | add:3, remove:3 | пусто | 0 ₽ |
| 3 | add:4, set:4:3 | товар 4: 3 шт. | 12 900 ₽ (4 300 * 3) |

## Изменения dataset

В отличие от работы 8, `products.json` в dataset работы 9 содержит четыре товара (Книга, Курс, Мышь, Клавиатура) только с полями `id`, `name`, `price`. Поэтому:

- `data/products.json` взят из dataset работы 9. Значения `id`, `name`, `price` не менялись. Добавлено только поле `category_id`, чтобы сохранить фильтр по категориям из работы 8: Книга в «Книги», Курс в «Курсы», Мышь и Клавиатура в «Аксессуары».
- Модель `Product` и `ProductRepository` теперь принимают товары без `category_id` и без `stock` (категория 0 означает «без категории», остаток `null` означает «остатки не ведутся», товар считается доступным).
- В `data/catalog_cases.csv` числа ожидаемых товаров пересчитаны под каталог из четырёх товаров (`all`: 4, `books`: 1). Раньше было 20 и 4.

## Ограничения

- Корзина привязана к сессии браузера (нет входа пользователя), после закрытия браузера пропадает.
- Остатки товаров не проверяются (в dataset этого поля нет).
- Нет защиты форм от CSRF, нет оформления заказа.
