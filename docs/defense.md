# Ответы на контрольные вопросы

1. **Какие входные данные получает приложение и где они находятся?**
   Файлы `data/products.json` (товары), `data/cart_scenarios.json` (сценарии проверки корзины), `data/categories.json`, `data/routes.csv`, POST-поля форм (`product_id`, `quantity`) и состояние корзины в `$_SESSION['cart']`.

2. **Какой участок кода отвечает за преобразование данных в интерфейс?**
   `CartController::index()` берёт позиции и итог у `CartService` и передаёт их в `View`, а `views/cart/index.php` выводит таблицу.

3. **Какое ошибочное состояние вы проверяли вручную?**
   Количество 0, отрицательное, нецелое или больше 99; несуществующий `product_id`; прямой заход на `/cart` в новой приватной вкладке; отсутствие `products.json`.

4. **Какие части решения вы бы изменили при увеличении объёма проекта?**
   Хранить корзину в базе данных для вошедших пользователей, добавить проверку остатков, CSRF-токен, оформление заказа, AJAX-обновление количества.

5. **Как проверить работу после чистого клонирования репозитория?**
   `git clone`, затем `php -S localhost:8000 -t public public/index.php`, затем пройти `docs/checklist.md` и открыть `/check/cart`.

## Дополнительно для защиты

**Почему в session только id и количество?** Название и цену можно получить из `ProductRepository`. Копия в сессии могла бы устареть после изменения цены.

**Почему изменения POST-запросами?** GET должен только показывать данные. Если добавление сделать ссылкой, обновление страницы или предзагрузка браузера изменят корзину. После POST делается redirect, поэтому F5 не повторяет действие.

**Где считается стоимость?** В `CartService::lines()` (позиция) и `CartService::total()` (итог). Представление только выводит готовые числа.

**Почему `CartService`, а не модель `Cart`?** Корзине нужны данные из репозитория и правила (лимит, проверка товара, расчёт суммы). Эти правила удобно держать в сервисе, а состояние хранится в сессии.

**Зачем ссылка `&$session` в конструкторе?** Сервис работает с массивом, который ему передали. В приложении это `$_SESSION`, а при проверке сценариев временный массив `$state`. Так реальная сессия не меняется, а проверяется тот же код.

**Почему `session_start()` в `index.php`?** Сессию достаточно запустить один раз до любого вывода. Представления только выводят данные и сессию не запускают.

**Как работает flash-сообщение?** Контроллер кладёт сообщение в `$_SESSION['flash']` и делает redirect. На следующем запросе `Flash::pull()` читает и сразу удаляет его, поэтому оно показывается один раз.

**Показать использование dataset:** изменить цену в `data/products.json` и обновить `/cart`: сумма изменится без правок кода. Или изменить шаги в `cart_scenarios.json` и открыть `/check/cart`.
